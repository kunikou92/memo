# メモアプリ 要件定義

## 1. 概要

Supabaseのメールアドレス認証を利用し、ユーザーごとに非公開のメモを管理できるWebアプリを作成する。

フロントエンドにはNext.jsのApp Router、スタイリングにはTailwind CSSを使用する。PCとスマートフォンの両方で利用できる、シンプルで分かりやすいUIを目指す。

本書は、最小構成の初期リリースに必要な機能、画面、データ、セキュリティ、環境構築および受け入れ条件を定義する。

## 2. 目的

- メールアドレスとパスワードでユーザー登録およびログインできること
- ログインしたユーザーが自分専用のメモを管理できること
- SupabaseのRow Level Security（RLS）により、他のユーザーのメモへアクセスできないこと
- Vercelへ安全にデプロイできること
- 機能を必要最小限に絞り、今後拡張しやすい構成にすること

## 3. 技術構成

| 分類 | 採用技術 |
| --- | --- |
| フレームワーク | Next.js（App Router） |
| 言語 | TypeScript |
| UI | React |
| CSS | Tailwind CSS |
| 認証 | Supabase Auth（メールアドレス・パスワード） |
| データベース | Supabase Database（PostgreSQL） |
| セキュリティ | Supabase Row Level Security（RLS） |
| ホスティング | Vercel |

## 4. 対象ユーザー

- メールアドレスを所有している個人ユーザー
- PCまたはスマートフォンの一般的なWebブラウザを利用するユーザー

## 5. 機能要件

### 5.1 認証

以下の機能を提供する。

- メールアドレスとパスワードによる新規登録
- 登録メールアドレスへ送信される確認メールによるメール認証
- 認証済みのメールアドレスとパスワードによるログイン
- ログアウト
- ログイン状態の維持
- 未ログインユーザーがメモ関連ページへアクセスした場合、ログイン画面へリダイレクト
- メール未認証のユーザーはログイン不可

パスワード再設定機能は初期リリースに含めない。

### 5.2 メモ管理

ログインしたユーザーは、以下の操作を行える。

- 自分のメモを一覧表示
- メモの新規作成
- 自分のメモの編集
- 自分のメモの削除

メモは以下の情報を持つ。

- タイトル
- 本文
- 作成日時
- 更新日時

### 5.3 削除確認

- 削除ボタンを押した時点では、まだメモを削除しない
- 「本当に削除してよいですか？」という趣旨の確認を表示する
- ユーザーが削除を確定した場合のみ、対象メモを完全削除する
- ユーザーがキャンセルした場合は、メモを削除せず元の画面に戻る
- ゴミ箱、論理削除、復元機能は設けない

## 6. 画面要件

初期リリースでは、次の4種類の画面を用意する。

### 6.1 新規登録画面

想定URL: `/signup`

- メールアドレス入力欄
- パスワード入力欄
- 新規登録ボタン
- ログイン画面へのリンク
- 入力不備や登録失敗時のエラー表示
- 登録成功後、確認メールを確認するよう案内を表示

### 6.2 ログイン画面

想定URL: `/login`

- メールアドレス入力欄
- パスワード入力欄
- ログインボタン
- 新規登録画面へのリンク
- 認証失敗時のエラー表示
- ログイン成功後、メモ一覧画面へ遷移

### 6.3 メモ一覧画面

想定URL: `/notes`

- ログイン中のユーザーが所有するメモのみを表示
- 各メモのタイトル、更新日時を表示
- メモが0件の場合は空状態の案内を表示
- メモ作成画面への導線
- 各メモの編集画面への導線
- 各メモの削除操作
- ログアウト操作
- 基本の並び順は更新日時の新しい順

### 6.4 メモ作成・編集画面

想定URL:

- 新規作成: `/notes/new`
- 編集: `/notes/[id]/edit`

共通要件:

- タイトル入力欄
- 本文入力欄
- 保存ボタン
- キャンセルまたは一覧へ戻る導線
- 入力不備や保存失敗時のエラー表示

新規作成時は新しいメモを保存し、編集時は既存メモを更新する。編集対象が存在しない場合、または現在のユーザーが所有していない場合は、内容を表示せず一覧画面へ戻すか、適切なエラーを表示する。

## 7. 画面遷移

```text
未ログイン
  ├─ 新規登録 ─→ 確認メール送信案内 ─→ メール認証
  └─ ログイン ─→ メモ一覧

ログイン済み
  ├─ メモ一覧 ─→ 新規作成 ─→ 保存 ─→ メモ一覧
  ├─ メモ一覧 ─→ 編集 ─────→ 保存 ─→ メモ一覧
  ├─ メモ一覧 ─→ 削除確認 ─→ 削除 ─→ メモ一覧
  └─ ログアウト ─────────────→ ログイン
```

## 8. データ設計

Supabase上に`notes`テーブルを作成する。

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | `uuid` | 必須 | メモID。主キー。自動生成 |
| `user_id` | `uuid` | 必須 | 所有ユーザーID。`auth.users.id`を参照 |
| `title` | `text` | 必須 | メモのタイトル |
| `content` | `text` | 必須 | メモの本文 |
| `created_at` | `timestamptz` | 必須 | 作成日時。自動設定 |
| `updated_at` | `timestamptz` | 必須 | 更新日時。作成・更新時に設定 |

データ上の要件:

- `id`はUUIDで生成する
- `user_id`はSupabase AuthのユーザーIDと関連付ける
- タイトルは空文字のみで保存できないようにする
- 本文は空でも保存可能とする
- 日時はデータベース上ではタイムゾーン付きで保存し、画面表示時に利用者向けの形式へ変換する
- ユーザー削除時のメモの扱いは、Supabase Authのユーザーに連動して削除される構成を基本とする

## 9. 認証フロー

### 9.1 新規登録

1. ユーザーがメールアドレスとパスワードを入力する
2. Supabase Authへ登録を要求する
3. Supabaseから確認メールを送信する
4. ユーザーがメール内の確認リンクを開く
5. メール認証完了後、ログインできる状態になる

### 9.2 ログイン

1. ユーザーがメールアドレスとパスワードを入力する
2. Supabase Authで認証する
3. 認証成功後、セッションを保持してメモ一覧画面へ移動する
4. 認証失敗時は、認証情報を確認するようエラーを表示する

### 9.3 ログアウト

1. ユーザーがログアウトを実行する
2. Supabaseのセッションを終了する
3. ログイン画面へ移動する

## 10. アクセス制御とセキュリティ

### 10.1 基本方針

- `notes`テーブルではRLSを必ず有効にする
- ブラウザから利用する環境変数には、Supabaseの公開用キーのみを設定する
- SupabaseのService Roleキーをブラウザへ公開しない
- 画面上の制御だけに依存せず、データベース側でも所有者を検証する
- 入力値は適切に検証し、本文を実行可能なHTMLとしてそのまま描画しない

### 10.2 RLS要件

ログインユーザーのIDと`notes.user_id`が一致する場合のみ、次の操作を許可する。

- `SELECT`: 自分のメモのみ取得可能
- `INSERT`: `user_id`が自分自身の場合のみ作成可能
- `UPDATE`: 自分のメモのみ更新可能
- `DELETE`: 自分のメモのみ削除可能

他ユーザーのメモは、IDを直接指定した場合も取得・更新・削除できないこと。

## 11. 入力・バリデーション要件

- メールアドレスは必須とし、メールアドレス形式を確認する
- パスワードは必須とし、最低文字数などSupabase側の設定に従う
- タイトルは必須とし、空白だけの入力は不可とする
- 本文は任意とする
- 保存処理の連続実行を防ぐため、処理中は送信ボタンを無効化する
- エラー時はユーザーが次に取るべき行動が分かる文言を表示する

タイトルと本文の最大文字数は、実装開始時に定数として決定する。初期案はタイトル100文字、本文10,000文字とする。

## 12. UI・レスポンシブ要件

- Tailwind CSSを使用する
- PCとスマートフォンの両方で横スクロールなしに主要操作を行えること
- フォーム、ボタン、メモ一覧はシンプルで一貫した見た目にする
- キーボード操作で主要機能を利用できること
- 入力欄には対応するラベルを付ける
- 処理中、成功、失敗の状態がユーザーに分かること
- 削除操作は通常の操作と区別できる見た目にする

## 13. エラー処理

- 通信エラー時は、時間を置いて再試行するよう案内する
- 認証エラー時は、メールアドレス、パスワード、メール認証状態の確認を促す
- 保存または削除に失敗した場合は、成功したように見せずエラーを表示する
- セッションが失効している場合はログイン画面へ移動する
- 存在しないメモやアクセス権のないメモの内容を画面へ表示しない
- 内部情報や秘密情報をエラーメッセージへ含めない

## 14. Supabase準備要件

Supabaseプロジェクトはアプリ利用者または開発者が事前に作成する。

実装時に以下を設定する。

1. Supabaseプロジェクトを作成する
2. メール・パスワード認証を有効にする
3. メール確認を必須にする
4. 開発環境と本番環境のSite URLおよびRedirect URLを登録する
5. `notes`テーブルを作成する
6. RLSを有効にし、参照・作成・更新・削除の各ポリシーを設定する
7. 更新時に`updated_at`を更新する仕組みを設定する
8. Supabase URLと公開用キーを取得する

## 15. 環境変数

ローカル環境とVercelに、少なくとも以下の値を設定する。

```text
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

実際に使用する環境変数名は、採用するSupabaseクライアントライブラリの推奨に合わせて実装時に最終確認する。値をGit管理対象のファイルへ直接記載しない。

## 16. Vercelデプロイ要件

1. GitリポジトリをVercelへ連携する
2. Vercelプロジェクトを作成する
3. Supabase URLと公開用キーをVercelの環境変数へ登録する
4. Vercelへデプロイする
5. 発行された本番URLをSupabase AuthのSite URLおよび許可するRedirect URLへ登録する
6. 本番環境で新規登録、メール認証、ログイン、メモ操作、ログアウトを確認する

プレビュー環境を認証フローの確認に使用する場合は、必要なVercelのプレビューURLもSupabase側で許可する。

## 17. 非機能要件

- 一般的な最新バージョンのChrome、Edge、Safariで利用できること
- 主要画面はPCとスマートフォンで利用できること
- 認証情報や他ユーザーのデータを漏えいしないこと
- 通常の操作に対して、処理中であることが分かる応答を返すこと
- TypeScriptの型チェックとLintを通過すること
- 秘密情報をリポジトリへコミットしないこと

## 18. 受け入れ条件

### 認証

- 未登録のユーザーが新規登録でき、確認メールが送信される
- メール認証前のユーザーはログインできない
- メール認証後のユーザーはログインできる
- ログアウト後はメモ関連ページへアクセスできない
- 未ログイン状態でメモ関連URLへ直接アクセスするとログイン画面へ移動する

### メモ

- ログインユーザーがタイトルと本文を指定してメモを作成できる
- 作成したメモが一覧へ表示される
- 自分のメモを編集でき、更新日時が更新される
- 削除ボタンを押すと確認が表示される
- 削除をキャンセルした場合、メモが残る
- 削除を確定した場合、メモが完全に削除される
- タイトルが空白だけのメモは保存できない
- メモが0件の場合、空状態の案内が表示される

### セキュリティ

- ユーザーは自分のメモだけを一覧表示できる
- 他ユーザーのメモIDを指定しても内容を取得できない
- 他ユーザーのメモを更新または削除できない
- 未認証状態でデータベースのメモを取得・作成・更新・削除できない
- Service Roleキーがクライアントやリポジトリへ公開されていない

### 表示・公開

- PCとスマートフォンの両方で主要操作を行える
- Vercelの本番URLで一連の認証とメモ操作を完了できる

## 19. 初期リリースの対象外

- パスワード再設定
- SNSログイン、OAuthログイン
- メールアドレス変更
- プロフィール編集
- メモの共有、公開、共同編集
- タグ、フォルダ、検索、並び替え設定
- 自動保存
- Markdownプレビュー、リッチテキスト編集
- 画像やファイルの添付
- ゴミ箱、論理削除、削除後の復元
- オフライン対応
- 管理者画面

## 20. 実装時の確定事項

- タイトルの最大文字数: 100文字
- 本文の最大文字数: 10,000文字
- 日時の表示形式: `YYYY年M月D日 HH:mm`（日本時間）
- メール認証後の遷移先: ログイン画面
- 削除確認UI: ブラウザ標準の確認ダイアログ
